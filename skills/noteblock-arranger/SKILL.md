# 音符盒编配

保持音乐母版冻结，另建游戏适配计划。先按整句音域、起音特征与声部职责选音色，再处理音区、持续和空间关系；逐音钳制或折八度会破坏旋律走向。

可信 MIDI 可以进入独立的 `arrange-game` 步骤。用源音符 ID 写出删减、换声部、改音高或微移起音的理由，导出可在 DAW 检查的演奏 MIDI、逐音差异和游戏触发谱。把改编作为独立候选听审，再交给实体轨道设计。

读[编配方法与练习](references/guide.md)。`plan-noteblocks` 默认整个角色共用一个槽和一组移调；确需分句换色时，显式采用按句适配或逐句指定槽位。超音域先依据报告选择采样根音或分区。使用校准样本后才决定如何延续长音。

原版音符盒不按MIDI note-off保持/停止，也不直接执行每音velocity；用样本、织体、路由与布局作有记录的近似。`onset`、`retrigger`、`carry`保留不同语义。

声音profile应明确角色→槽→声音事件/基底→样本根音/包络。先检查共用槽和音色连续性，再听主读、低频、长音、高潮及移动跟拍。

交付适配计划、事件、变换/损失表、独奏/混合试听和仍需客户端验证的部分。进入实体机器前，每个源音有去向，时序与音高在声明的profile下可解释。
