# 从音乐功能到效果动作

## 三个尺度

| 尺度 | 音乐依据 | 设计 |
|---|---|---|
| 单音节点 | 源onset、音高、角色 | 闪亮、展开、碎散、淡出；轮廓在观看距离可辨 |
| 持续轨迹 | 源结束时间和乐句方向 | 连续线芯/色带与受控细节；不把补触发当新爆发 |
| 乐句动作 | 角色交接、段落边界和张力变化 | 跨轨连接、展开/收束、主色和空间层次变化 |

小尺度说明“谁在演奏”，大尺度建立发展。给主读留对比与中央视线，最大动作放在有意义的乐句，不让每个鼓点都满屏爆炸。

## 学习ColorBlock的方法

参数曲线定义位置，时间变量定义渐进生成和运动；旋转/缩放/平移将同一词汇部署到不同角色。寿命内颜色、透明度、尺寸和速度可形成精细层次。光点、线框、环、螺旋和曲线不是唯一风格，可在相同语法下变化。

先做一个节点、一条持续轨迹和一次跨轨动作，逐个观察起音、稳定阶段与退场。不要从分镜猜作者完整公式，也不要把原作品纹理/视频直接放进自己的公开样例。

## 工具与时钟

```shell
python run_pipeline.py compile-show examples/show_study.json --out work/show-study
python run_pipeline.py compile-show work/music-lesson/adaptation/events.json --out work/music-show
```

score/style字段以工具schema和学习例子为准。资产保存音乐GT、角色、锚点、参数和种子，后端负责渲染。原始音符、承接与补触发保留来源，停止/跳转按统一演出时钟恢复。

原创几何例子明确列`node/ring/helix/bezier`、`beginGT/endGT`、position、color、radius、points，Bezier另有controlPoints；音乐输入则按角色和源时间生成候选。`--style`可设namespace、sampleKey、colors和captions。输出`show_score.json`与`effect_contact.png`，后者用于初步几何检查，不能证明游戏中的连续运动。

相机跟随的动作与世界固定节点分别设计。一直贴在镜头上的宽带容易像HUD；出生后固定世界位置的细节可以让相机穿过。近距效果应有退场，避免遮满画面。

## 字幕

有可信文本再做字幕，ASR只是草稿。cue包含ID、begin/end、文字、位置与效果，读取音乐时间。检查长句换行、安全边距、F1、重播和中途停止；不得为对齐一句文字随意改全局时钟。

## 成功与失败练习

用同一个原创样段生成三层效果，先看关键时刻再录完整连续运动。比较两种尺寸/密度，观察主读、连续性、细节与留白；记录平均/P95帧时和实际光影。

故意把所有retrigger当onset，或在重播时不清历史trail。应从来源计数或实际残留定位原因，修复后开→关→开、中止→完整重播、卸载世界都无残留。视觉开关前后实体音乐事件一致。

## 后端选择

自有Fabric、Photon或ColorBlock系接口分别报告支持的效果与限制。Fabric旧移植不自动拥有Photon2时间轴；NeoForge模组不直接放入Fabric实例。以相同音乐、机位、场景与光影做对照，采用实际能达到用户目标的版本。

## 退出条件

核心角色可读，持续/起音语义正确，乐句发展与字幕清楚；实际客户端覆盖目标段落，性能和生命周期通过，用户认可具体候选。静态预览、JAR编译与cue数量都不能单独作为艺术完成证据。
