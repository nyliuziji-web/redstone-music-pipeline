# 按证据诊断

先保存当前候选、输入hash、命令与错误，不删除旧版本。报告来自哪一层：文件、服务端、客户端、用户听看还是录制。以下顺序优先排查容易造成整条链错误的假设。

| 症状 | 先检查 | 修复与复验 |
|---|---|---|
| `.mid`打不开或曲目明显缺段 | 实际文件头、解码、时长、版本、段落覆盖，是否下载到HTML | 更换真实来源；不要用循环片段填满长度声称完整转写 |
| 所有音符逐渐错拍 | tempo map积分、独立空头、逐间隔取整累积 | 回到绝对秒统一量化，远隔段交叉检查 |
| 旋律起音对，长音听不到 | MIDI note-off/踏板与样本自然衰减分开听 | 比较只改时值、换样本、持续层或局部补触发，保留源起音 |
| 声音忽高忽低或忽换乐器 | 折八度、逐音音域回退、样本中心和sounds.json附加pitch | 按完整乐句分配音色；实际低/中/高音测频 |
| 调小伴奏，主旋律也小 | 两角色是否共用同一声音事件 | 分槽并同步基底、profile、包与期望；同增益独奏/混合比较 |
| 延音颤动、糊或密集爆响 | 样本起音与变速后长度、重触发间隔、复音叠加 | 减少重触发、换包络/织体；每次只改一个变量 |
| 资源包存在却静音/仍原音 | ZIP根、事件与文件路径、大小写、OGG解码、启用优先级、`replace` | 校验定义后实际进游戏；服务器note正确不证明样本加载 |
| 军鼓变音或保存重开变样 | 沙等重力基底、邻居更新、方块状态与区块加载 | 修复承托/状态，保存重进后再对比真实事件 |
| 停止后还有声音或特效 | 未取消调度、残留脉冲、历史trail、world/run身份 | 只清理作品自有对象，检查中止后日志，完整重播 |
| 相机坐标对，画面仍卡 | 逐帧位移、插值目标、绑定先后、渲染中心与加载窗口 | 同机位小样比较，不能只看服务端目标点 |
| 模组不能启动 | Minecraft/Loader/Java/API、JAR元数据、传递依赖与mapping | 锁工作组合，按目标版本查源码；不要盲升全部依赖 |
| 光影中粒子过暗/发白/遮挡 | 材质混合、透明叠加、发光与真实照明、主读位置 | 同机位开关光影；先调轮廓/亮度层次再加数量 |
| 录制文件有画面无声音 | 音频设备、OBS轨、静音测试配置、真实音源与编码 | 短试录并解码检查再完整录；不能仅凭录制状态成功 |
| 任务结果被判过期 | 输入/配置/上游产物hash已改变 | 新建当前版本任务，把有效创意重新绑定输入，不篡改签名 |

## 最小复现

选能说明问题的最短范围，加足预运行和尾音；保留输入、原始结果、候选、测量和实际听看文件。做同段同机位或同响度比较，避免把不同曲段、不同音源和不同声音设置当作A/B。

同因失败两次时，记录已排除的原因、仍不确定的事实与替代路线。外部访问失败与模型能力不足分别处理；前者不应阻止已经有素材的离线工作。

## 避免假修复

不要删除断言、把期望改成错误输出、隐藏静音、把主唱重新归一化后称混音改善，或把客户端缺失的证据写成已通过。运行`status`/`handoff`，只失效真正受影响的层，保留认可基线。
