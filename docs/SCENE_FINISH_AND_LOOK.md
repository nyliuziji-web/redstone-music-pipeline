# 音轨场景收尾与 Nevada 画面配置

先让一段代表段的演奏、音轨、稳镜头和粒子通过实机复看。保留这份世界，再从同一谱、音色包和镜头制作场景候选。输入是通过保护检查的实体机器、已定的镜头及一份可以重播的原版世界。交付包含原版世界、阶段蓝图、实机检查记录和可选的录制画面配置。

## 1. 在实际镜头里决定加什么

1. 关掉粒子完整走一遍，用起点、左右轨交接、最密的复音和句尾四个位置停看。标出发声的音符盒、近远轨的轮廓、相机通道和画面空白。粒子打开时再复看这四处，把会被遮挡的亮点和长音轨迹记下来。
2. 先收拾贴轨方块。用短支撑、包边和少量固定灯说明音轨的分组、转折或高差。让暗面压住杂乱接线，让音符盒顶面与前缘可见。灯优先放在转折和视线确实需要提示的位置。装饰和透视随音轨走，给每组构件留出维修空间。
3. 再做两侧和远处。把地形最高轮廓压在主要音符盒以下，沿镜头方向用不等高的短坡、台阶和少量材质变化制造近远层次。保留中央视线与落差，让相邻轨在斜视时也能分开。若新背景轮廓正好切过发音位置，把岸肩下压或向外退。大片连续亮面会和亮芯抢对比，优先用低反差石材。
4. 初版仅处理一个代表段。先看静态轮廓，再原速复播，最后才决定其他段落是否需要延续、留空或换地形结构。只改地形时保留镜头姿态，便于判断哪里真正改进。

## 2. 岸景版的做法和可复现练习

《音轨流光》岸景候选沿用已认可亮芯版的同一 20.6 秒演奏、细窄包边和稳镜头。两侧用深板岩塑造高低起伏，内缘用深板岩瓦标出层次，少量凝灰岩和磨制玄武岩打断整片重复。背景最高到 Y=87，中间留空。地形参数只属于这段机位和这套机器，换曲时以俯视和镜头画面重新定边缘、坡高和材质。

可从 [原创《三水道》轨道练习](PHRASE_TO_WORLD.md) 的短段机器产物开始。下面是项目根目录执行的 Python 入口，尖括号中的内容换成实际路径。机器产物目录从项目 `state.json` 的 `stages.machine.artifact` 取值，相对路径以该制作项目根目录解析。

```text
python examples/track-study/build_banks.py <机器产物目录> --out <候选项目>/banks-stage.json
```

有已验收的逐方块装饰时，加 `--existing <装饰蓝图.json>`，脚本会保留其中的 `blocks`。旧蓝图如果用 `operations` 表达，例程会明确拒绝。先用独立候选试地形，要沿用旧场景时再把旧装饰落实为明确的方块坐标并合入。例程覆盖通常的 80 格走廊中央机位和 4–21.6 秒短段。改横向距离、最高高度和带宽后都要重新过保护检查。

把新蓝图路径填入候选项目 `project.json` 的 `inputs.stageModule`，运行 `python run_pipeline.py run <候选项目>`。查看新机器产物的 `stage_module_report.json`，处理保护拒绝，尤其注意音符盒上方空气、基底、红石邻域和相机通道。遇到碰撞先把整块坡或装饰移开并重跑。对合入后的 `placed_blocks.json` 运行 `python run_pipeline.py preview-track <placed_blocks.json> --out <预览目录>`，确认两侧都有地形、中央空隙连续。若原版含粒子，用同样的参数从新机器产物重新执行[原版轨道粒子示例](VANILLA_RAIL_PARTICLES.md)生成候选世界。

## 3. 原版进游戏验收

1. 候选和基线使用两个存档。保持世界时间、FOV、视距、画质和粒子档位一致。先关闭粒子，看轨道轮廓、发音面、维修可达性以及控制区有无被地形盖住。尤其复看轨道入画、有近景掠过和音乐最密的几个时刻。
2. 切逐音，抽查近侧独奏、远侧发音和同刻复音。若远侧亮点被岸肩或贴轨边框遮住，先移几何；若位置都看得见但亮度接近背景，再压背景颜色或减少局部固定灯。
3. 切完整，扫过沿轨传递和乐句动画的起、中、尾。开过粒子的镜头里也要能找到负责发音的轨道。中途停止并重播一次，核对粒子收尾、音乐触发和视线。
4. 对比发音的时间、坐标与音符，校对声音包和已经认可的粒子函数。记录服务端、客户端接收、实际画面三个层次。命令成功或客户端收到粒子只能证明触发链；遮挡、曝光与画面主次需要截图或观看原速实录来判断。

## 4. 最后试用 Nevada 的材质与光影

Nevada 的录制实例为 Minecraft Java **1.21.1**，使用 Fabric Loader **0.18.2**。以下版本来自该实例的资源包、光影和启动配置。新世界先验收原版，录制前再用独立实例试装以下可选组合。

| 用途 | Nevada 里使用的版本 |
|---|---|
| 方块材质 | **Faithful 32x for 1.21.1**，实例文件名 `Faithful 32x - 1.21.1.zip`。[Faithful 官方 1.21.1 下载目录](https://database.faithfulpack.net/packs/32x-Java/June%202026/) |
| 光影 | **Solas Shader 3.9**，实例文件名 `Solas-Shader-V3.9.zip`。[作者发布页](https://modrinth.com/shader/solas-shader/version/3.9) |
| 可选红石辨识材质 | **Visual Redstone Vanilla Plus 1.4.1**。需要辨识线路状态时再加，放在 Faithful 上方。[作者发布页](https://modrinth.com/resourcepack/visual-redstone-vanilla-plus/version/1.4.1) |
| 光影客户端 | **Iris 1.8.14-beta.1** 与 **Sodium 0.8.13** 的 Java 1.21.1 Fabric 构建。按版本页依赖说明安装。[Iris](https://modrinth.com/mod/iris/version/1.8.14-beta.1%2B1.21.1-fabric) · [Sodium](https://modrinth.com/mod/sodium/version/mc1.21.1-0.8.13-fabric) |

把外观材质 ZIP 放实例的 `resourcepacks/`，光影 ZIP 放 `shaderpacks/`，兼容的客户端模组放 `mods/`。世界自带的声音资源包随存档保留。先只开 Faithful 看音符盒、标记和粒子，再开 Solas 看同一段。Faithful 会覆盖部分原版粒子纹理，Solas 的曝光和辉光也会改变亮芯与背景的反差。若粒子融进亮面，先对照关闭光影的同段录制，再逐一试辉光、曝光和场景固定光。最终短试录一次，观察镜头最密处的帧时间、粒子轮廓与音色，记录实例版本和设置。公开集成包只提供这些链接与配置说明，画面套件由使用者自行下载。
