# 让音符盒音轨成为主体的原版粒子演出

在 Java 1.21.1 原版上，用音乐机器已经导出的方块坐标和局部节拍，做逐音亮点、沿轨传播和乐句动画。这一章以《烟袋斜街 · 音轨流光》20.6 秒的制作与反馈为例。包内练习用原创《三段水道》。先做代表段，同机位看清楚轮廓、发声点和声部层次。

## 1. 粒子关闭时先看音轨

1. 从 `state.json` 的 `stages.machine.artifact` 找到实际机器目录。打开 `expected_events.json` 与 `track-plan.json`。逐段标出哪个实体音符盒声部应在近景或中景，哪里需要露出两组声部的交接。
2. 以预计的跟拍镜头看实际编译坐标。最少取开头、第一段主奏进场、最密刻和结尾四处。看正在发声的盒子有没有出画、被侧轨挡住、被亮面抢走注意力。仅用俯视图容易高估中轴铺面的价值。
3. 先删除占据画面却没有音乐功能的结构。从原舞台蓝图里移掉这些模块，重新合入。需要辨认轨道时，用贴近电路的窄托架、细边或间隔灯点。修改前后对比音符盒、底座、时刻与调音。原版灯光环境改变时再看音乐机器是否仍读得清楚。

《音轨流光》的修订移掉中央铺面与大部分独立装饰，把保留的灯点和窄托架贴到音轨上。镜头加了 `layout.camera.followBack: 8`，朝向、俯仰保持固定。按 70° 垂直视野和 16:9 画面估算，主奏发声时投进画面的音符盒中心从 29/63 增为 63/63。这是没有计入遮挡的构图检查。保留原版声包和 294 个音符盒的坐标与起音。自己的作品先用 `preview-track` 核对位置，再进游戏看完整连续镜头。后移、抬高和扩大 FOV 都应先试其中一个，避免用摇头来补出画。调整后也要复听同机位的轨道音量。见[轨道与稳镜头](PHRASE_TO_WORLD.md)。

## 2. 把三种动作分开

| 层 | 时钟和位置 | 具体做法与复查 |
|---|---|---|
| 逐音触发 `hits` | 取 `expected_events.json` 每颗实体音符的 `q/x/y/z`。从音符盒顶部发射 | 同刻发声的不同盒子各有自己的亮芯。使用一团白色 `end_rod` 和扩张的有色尘环。主奏的环持续四个采样时点，伴奏短一些。用 `notes` 模式看单音能否点亮正确的盒子。补触发属于持续层，本示例不为它生成第二次攻击爆点 |
| 沿轨传递 `traces` | 将同乐句、同声部的相邻原始起音配对，使用两颗实体盒子作为首尾 | 在间隔内逐刻插值，纵向沿实际轨道移动，高度用正弦弧稍微抬起。亮芯带两侧弱点，轨迹到后一颗音即收束。距离过远、段界错开或间隔过长时略过，防止把不同房间连成一条带 |
| 乐句动画 `phrases` | 读真实段界。第一个动作等开头建立，后续各段在起点触发 | 每两 GT 采样一次。三层弧从同一乐句定位，分别延迟 0、5、10 刻。半径按时间扩大，转角连续变化，层间有相位与深度差。用视线下半部的缺口保留窗口，形状变大后缩小点并自然退场。停在中段看三层是否能区分，再连续播放检查有无闪断 |

背景 `ambient` 只在边缘和较空的时刻补少量点。主奏、内声、回声、回答用不同色，亮度峰值留给要读的音和乐句变化。先让三层分别说得通，再听看完整演出。

## 3. 原版指令和独立练习

精确形状用一条指令放一个点，delta、speed 皆为零。随机云在一个中心发射多颗，可以用作亮芯或余辉。它的散射点不会沿数学曲线均匀排开。下面的语法用于 Java 1.21.1。

```mcfunction
particle minecraft:dust_color_transition{from_color:[1f,0.72f,0.27f],to_color:[0.6f,0.49f,0.32f],scale:2.6f} ~ ~1 ~ 0 0 0 0 1 force @s
particle minecraft:end_rod ~ ~1 ~ 0.45 0.28 0.45 0.035 14 force @s
```

先按[原创水道练习](PHRASE_TO_WORLD.md#2-先做实体布轨再画建筑)构建机器和稳镜头。把下面的 `MACHINE_ARTIFACT` 换成包含 `expected_events.json`、`placed_blocks.json` 和 `world/` 的实际机器阶段目录。

```shell
python examples/vanilla-particles/build.py MACHINE_ARTIFACT work/rail-fx
python examples/vanilla-particles/build.py MACHINE_ARTIFACT work/rail-fx-bright --density 1.45 --width 1.26 --scale 1.52 --viewer-radius 54 --daytime 12850
```

两条命令生成各自独立的世界，输出目录须为新目录。程序在复制的控制包中接到原机器 `tick` 的末尾，从已更新的 `#q` 取帧。只有播放态才发送粒子。停播会停止新发射，已送达的原版粒子按自身寿命消散。生成的 `particle-budget.json` 记录各层请求数及单刻命令峰值。保留源机器的块、声音包、光影基准，以便做单变量比较。

## 4. 不显眼时按顺序调

| 现场看到的问题 | 优先改一个变量 | 复验 |
|---|---|---|
| 发声点很小，近处也看不到 | 提高 `--scale`，给盒子上方加入浅色亮芯，并略降背景发射。示例把重点环的尘粒放大，且提升 `end_rod` 云的数量。粒子颜色变暗时要留一点可辨的亮度 | 用 `notes` 模式停在中间距离。若亮团把盒子整个盖住，先降亮芯持续或散布 |
| 远处像虚线、展开只有一小簇 | 在同一圆弧上提高 `--density` 补点。要拉宽声部两侧的覆盖，用 `--width` 扩大环或弧的半径。扩大半径后先看边缘是否出画，再填大间距 | 看实际镜头的近、中、远景。密度是几何采样点数，宽度是方块尺度。两者分别调整 |
| 有大量粒子，乐句动画仍看不明白 | 减弱一直发射的背景。示例只在空档发边缘点，独立动画有成形、扩大和退场。比较傍晚背景与亮白芯的对比 | 同一机位从首帧完整看到最后一帧。先辨认轮廓，再看色彩。背景给重点让路，避免把轨道吞没 |
| 跟拍距离一远就全消失 | 看发射到观众的距离与粒子选项。用 `--viewer-radius` 改接收半径。它控制发给谁，空间半径仍由 `--width` 控制 | 在独立世界切换「粒子：全部」，检查模式、实际坐标和目标观众。服务端成功发指令只证明尝试送达 |
| 峰值时卡顿、左右轨同时亮成团 | 打开 `particle-budget.json` 查峰值命令，先降低背景密度，再把弧层错开或降低低优先级起音的持续 | 实机对照关闭和完整档，再试录短段。210 次/刻是样例生成器上限，客户端粒子数和帧率要另测 |

《音轨流光》第一轮扩大发射量后，用户仍觉得不显眼。后续亮芯候选把逐音层的请求量从约 5,410 提到 10,790，背景层从约 5,103 缩到约 692。关键变化是亮点的位置、尺寸、背景对比和发射的集中时机。这些数字属于相同 20.6 秒世界的设计预算，是否醒目以实际观看为准。

## 5. 进游戏验收

1. 在 Java 1.21.1 原版将生成的世界复制为新存档，接受资源包，游戏粒子设为「全部」。固定 FOV、视距、画质和相机。先执行 `/function rail_fx:off`，再用世界自身的开始指令看纯轨道。
2. 用 `/function rail_fx:notes` 重播。抽一颗独奏、一个同刻复音和一个句尾。看每次亮点的位置是否贴住真实发声处、左右声部是否清楚。先验三处，再看整段。
3. 用 `/function rail_fx:full` 重播。选一个实际交接处，核对亮点确实沿轨移动，整组弧形有动画方向和退场。检查近处遮挡、远处能否辨认，音乐休止是否安静。记录想修的具体秒数、声部和观察条件。
4. 在最密处中止，观察停止后新粒子是否停发，允许旧粒子自然消散。再完整播放一次，核对音乐没有错音或漏音。安装了本机观察器时同时保存 `expected_events.json`、启停与重放日志。要录制时用相同设置短试录，检查实际帧时间和声音。
5. 给用户看关闭、逐音、完整中的必要对照。回传具体问题时先选一层修订。服务器结果、客户端接收、静态构图和实际观感分别记录。

粒子获得认可后，可按[音轨场景收尾与 Nevada 画面配置](SCENE_FINISH_AND_LOOK.md)做独立地形候选。尤其在改变背景明暗或加材质、光影后，重新检查亮芯与背景的反差。
