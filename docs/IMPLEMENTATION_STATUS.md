## 0.3.0a1 音乐能力升级

2026-11-19。面向只拿到录音、只有可靠旋律、需要游戏配器三种起点。

- 音频候选使用独立解释器运行。Basic Pitch 保存原始模型输出和 MIDI。Beat This! 输出节拍及强拍。audio-separator 分人声与伴奏，已实测 CPU 下载首次运行和缓存离线运行。原曲与候选保留同一零点，试听报告标出末音、时长差和候选之间有分歧的位置。转写后端的使用方法见[本机音频后端](../integrations/transcription/README.md)。
- 编曲工具保留源 MIDI、踏板、速度和冻结主题，支持限域修订、增加声部和导出。采用固定提交的 music-skill 和弦进行助手。在原创 16 小节上实跑两种伴奏，均用 FluidSynth 2.6.2 与 GeneralUser GS 渲染了混合与独奏，并使用 FFmpeg 生成等响度比较。
- 音符盒的默认适配以整条声部为单位统一槽位。原创 20 秒练习制作了三组不同音体、可独立调整的声音槽、25 格校准和同一采样的长音对照。MIDI 61–82 的旋律由根音 72 的单槽覆盖，零八度偏移。额外音符盒模组未列入默认环境。
- Windows 本地自动测试 117 项，116 通过，1 个需私有 Nevada 素材的回归跳过。测试包含实际 Basic Pitch ONNX 和 Beat This! CPU 推理。已完成的测试不替代用户听审。
- 全新环境只安装 wheel 和普通生产依赖，成功读取自带 Skill、调用固定版本和弦连接助手并完成 8 秒 demo。另从 `--reference-audio` 新建项目，使用原创已知谱走音乐任务交付，导入七槽声音包，完成六阶段构建与交付 ZIP 检查。该测试验证导入与构建，转写质量由独立实验评价。

在有真值的 20 秒原创素材中，干净主旋律的 80 音里有 79 音被 Basic Pitch 命中。混音直接转写得到 197 音，其中 121 音能与已知的 130 个有音高源音一对一匹配。两项均按同音高、起音相差不超过 50 ms 统计。混音候选还需要清除多报和补齐漏音。真实歌曲的 30 秒样段已生成原录音、旧谱、混音直转和分出人声后转写的试听。缺少准确对照谱和听审结论。

本版试听为离线 GM 和采样近似，仍需用户反馈与实际游戏验证。MuScriptor 接口需要另配授权权重，本轮未实测。只给混音时，默认先通过样段决定转写与重编的比例。

## 0.2 实际验证

干净的 Python 3.12.16 独立环境安装 production / pitch / dev；实际 numpy、NBT、MIDI、SoundFile、music21、SciPy、TinySoundFont 小操作通过；librosa、SwiftF0、FFmpeg 在测试中处理原创音频。GM 只有引擎测试，尚无选定的发行 SoundFont。

统一测试 91 项，90 通过、1 项私有 Nevada 素材回归按预期跳过；Windows/Linux GitHub CI 与独立 Fabric 构建均成功。CI 首次通过提交为 `21a537b`，运行号 `44053833393`。8 个 Skill 通过官方 quick_validate。声音底座映射另用实际 1.21.1 named 游戏类核对，错误底座和非法 profile 的修复任务均有回归。

源码 wheel / sdist 已实际构建。独立 wheel-only 环境（Python -I，核心依赖，没有源目录导入）通过 bundle-check，并完整跑通 8 秒 demo 六阶段；wheel 内 bundle-export 导出 120 个源码/知识文件并保留完整工作入口。源码包后续新增原创案例后文件数量会变化。

标准 JDK21 / Loom1.9.2 / Yarn1.21.1+build.3 / Gradle8.12.1 运行 JAR 构建成功，实际 remap 为 intermediary 类名，ZIP 与作品 score 再打包检查通过。构建 JAR SHA256：`e5b1dcfc9960912c5f4d7663fc322108972be87feb9eb33a0b87ad11e044cddf`。这不授予客户端已实际运行。

独立新 agent 未继承开发对话，仅读取公共工作包，原创《窗外月迹》：12 小节、72 BPM、40 秒、56 源音、四个原创声音槽、零移调；15,558 世界方块含 512 装饰方块，73 个演出动作。正式任务导入与六阶段构建到 candidate_ready，Anvil/Litematica 独立回读、ZIP CRC 通过。详细[冷启动审计](COLD_START_REPORT.md)。

冷启动曾需要维护者修复合法 namespace 连字符被视觉校验拒绝的问题；因此本次不称为“初版零干预通过”。另发现单模块跨度限制和全景预览可读性问题，已补教程/结构化错误路线。
