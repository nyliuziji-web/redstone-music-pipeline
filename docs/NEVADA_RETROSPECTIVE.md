# Nevada正式复盘：从一次作品到可交接的制作能力

日期：2026-11-17。用途：为集成包改写提供经验依据。本文提取方法、失败模式和能力缺口；不包含原曲、歌词、MIDI、采样、游戏文件或私有运行环境。

## 1. 首作证明了什么

Nevada完成了音乐母版、音符盒声音适配、实体红石机器、跟拍、粒子、场景补光、轨道装饰、字幕、用户录制剪辑与发布材料准备。用户确认完整跑通。没有投稿成功的记录，也没有收到最终成片以逐帧复核。

历史交付记录：音乐约208.724秒，6,604次物理发声，其中4,430次原始起音与2,174次持续音补触发；最终场景385,953个非空气方块，13段、43个大型视觉动作、30条字幕。这些是案例统计，不是新曲的模板常量。

公开v0.1另有自己的验证边界：原创8秒demo完成六阶段构建和真实服务端触发/中止/重播；公共测试47项中46通过、1项私有回归跳过。通用客户端曾编译成功，但该软件版本没有完成新生成画面的实际客户端/听审/录制验收。[验证记录](../PIPELINE_VERIFICATION.md)

**结论：首作证明路线能成立，v0.1证明部分执行内核可复用；尚未证明一个无历史上下文的新agent能独立制作另一首完整作品。**

## 2. 过程中的关键决策

| 转折 | 实际发生的事 | 应提炼的能力 |
|---|---|---|
| 参考到母版 | 曲目版本、长度、BPM与网站谱并不一致；下载物还有错误页面、缺段转写 | 输入体检、版本辨认、来源登记和全曲覆盖判断 |
| 样段到全曲 | 起音/音高正确，用户仍反馈长音不足；需要区分MIDI时值和音色自然衰减 | 有依据的编曲修订、独奏/混合试听、单变量比较 |
| MIDI到游戏 | 普通中继器精度与音符盒声音行为不符合通用MIDI假设 | 独立游戏适配层、1GT相位模块、近似损失说明 |
| 样机与相机 | 沙子掉落、停止后残脉冲、逐刻传送卡顿；坐标日志不能证明画面平滑 | 实际电路观察、复位、相机插值和客户端测试 |
| 声音定稿 | 主题、伴奏、低频分别适合不同候选；共享flute槽使主唱随pad一起变小 | 按角色选音、路由诊断、分槽与移动空间混音 |
| 粒子实现 | 依赖版本、绑定时机、渲染中心和拖尾历史导致问题；最终采用自有几何绘制 | 版本查证、生命周期管理、效果语言与后端分离 |
| 场景整合 | 光影并未解决休止时可读性；字幕阅读期间应固定 | 早期光影抽测、固定补光、相机视线与字幕设计 |
| 交付 | 可玩世界、投影、控制包、声音与客户端版本必须成套；用户最终亲自录剪 | 版本绑定、安装收据、录制负载与成片检查 |

## 3. 应保留的判断原则

1. 音乐先明确角色与段落，技术适配保留来源；原始母版与游戏改编分别冻结。
2. 按绝对时间推进。tempo map换算秒，再统一量化至GT；补触发、承接和原始起音保留不同语义。
3. 先做覆盖风险的代表样段，再扩全曲；样段应覆盖主唱、长音、密集段、交接、休止和停止重播。
4. 冻结认可成果，局部修改产生新候选，检查受影响层；可恢复构建与回滚减少重复劳动。
5. 用实际可听、可玩的产物与用户沟通。默认agent自主推进，代表样段和最终成品请用户听看。
6. 文件正确、服务端正确、客户端正确、艺术认可、成片完成分别记录，证据绑定具体版本。
7. 艺术判断保留选择空间。Nevada的配色、15类角色、3刻相机、固定布局与具体采样增益是案例决策，不自动升级为所有作品的强制规范。

## 4. 把失败转成可交接能力

| 失败/返工 | 直接原因与更深缺口 | 集成包应提供的补强 | 新agent应能完成的练习 |
|---|---|---|---|
| 有文件却没有完整音乐 | 信任扩展名、网页描述和自动谱；缺统一输入验收 | 真实字节/时长/段落检查、来源表、缺项处理路线 | 识别伪MIDI、错误版本与缺失中段 |
| 长音听起来消失 | 将note-off长度当成真实声音持续 | 双预览、样本包络与持续策略工具，音符盒编配Skill | 区分缩短时值与快速衰减，提出并比较两种修复 |
| 主唱被一起压低 | 不同角色共享声音事件，缺路由表 | sound profile、槽位冲突检查、同增益独奏 | 找到共享槽根因并同步修正基底、包与期望 |
| 固定补触发造成颤动 | 从经验常数推全曲，未结合样本与乐句 | 起音/补触发差异、低中高音试听与代价报告 | 在连续音、短句和密集和声中选择不同策略 |
| 机器保存后行为不同 | 掉落、邻居更新、加载和复位影响状态 | 独立导出回读、实际事件追踪、保存重进测试 | 拒绝会破坏基底/音符盒上方空气的装饰 |
| 相机位置对但画面卡 | 只验证目标点，没有逐帧运动证据 | 固定相机模块、真实帧记录、加载中心检查 | 同机位比较相机方案并定位卡顿来源 |
| 效果画出来但表现单调 | 效果语言与Java实现耦合，缺统一风格和段落编排 | ColorBlock类参数化效果词汇、数据化演出与实际对照 | 做出节点、长音轨迹、乐句动作，避免同模板铺满 |
| 依赖升级后无法启动 | 仅按名称/标签选最新版 | 锁文件、元数据检查、版本源码查询和隔离实例 | 诊断不匹配依赖，保留已工作的组合 |
| 换agent仍要口头解释 | 教程引用私有脚本、素材、路径和旧状态 | 单一入口、自包含样例、状态/决策/证据合同 | 只凭公共包接手一个中断的新项目 |

表内“集成包应提供”是改写要求，不表示对应工具已经实现。

## 5. 对当前项目的正式评估

### 保留的资产

- 严格MIDI读取、来源hash、可恢复阶段、不可变产物、锁和过期任务拒绝。
- 奇偶双路物理时序、动态加载、启停/复位、三刻插值相机的验证经验。
- Anvil/Litematic独立回读、实际服务端事件追踪、交付白名单与hash校验。
- 首作的单变量试听、分角色选择、声音路由、代表样段、视觉生命周期和安装收据方法。

### 必须重新组织的部分

- **入口**：旧手册与新CLI描述有历史矛盾，公共包未包含完整专业教程。
- **创作层**：现有角色指南过短，不能替代编曲、音符盒适配、音色与视觉专业方法。
- **工具层**：音乐分析、试听、声音包制作、建筑预览等仍散落在Nevada专用脚本或研究中。
- **合同**：当前专业任务以MIDI导入、review和少量配置patch为主，表达不了完整创作产物。
- **运行环境**：客户端编译仍可回退到私有runtime.json；安装工具依赖旧机器的classpath/游戏实例。
- **风格与布局**：模板还有固定坐标、角色偏好和Nevada遗留命名；这些应成为命名清楚的profile或数据。
- **验证**：doctor偏“模块存在”，缺真实能力探测；阶段技术通过未形成完整创作评审状态。

遗留`nevada`字样不一概等于缺陷：内部已替换的模板名称与真实外部依赖分别处理。要验收的是新曲在无Nevada目录、无私有配置时可工作，以及未声明的坐标/风格假设不会泄漏。

## 6. 复盘转成下一版的标准

集成包应让agent知道“为何这样做、何时换办法、工具如何运行、怎样判断完成”，同时留给它实际创作与诊断空间。每项专业能力至少配一个原创成功样例和一个故意失败样例；大规模重模型不能代替这些基础能力。

最终成功标准是另一首作品的冷启动与中途接手验证，而不是资料数量、命令数量、八秒demo或本项目测试全部通过。完整改写决策见[改写方案](REWRITE_PLAN.md)。

## 7. 证据定位

原开发工作区的证据入口包括`nevada/STATUS.md`、最终`scene_full_v01/release_manifest.json`、声音研究、相机研究、粒子与场景验证，以及`production/pipeline_validation_2026-11-17.json`。这些私有文件不构成公共使用前置。

公开包用本文保存必要结论，以原创学习样例复现失败模式；不要求新agent取得旧聊天、原曲分轨或原来的本机目录。历史成绩、当前公开能力、计划新增能力必须继续明确区分。
